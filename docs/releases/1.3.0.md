# Mage-OS Shopping Feed 1.3.0

Status: release candidate, not yet tagged or published. Release date will be recorded at publication.

Version 1.3.0 adds XML output, conditional column values, attribute-based product selection, and ordered per-column modifiers. It combines PRs [#25](https://github.com/mage-os/module-shopping-feed/pull/25), [#26](https://github.com/mage-os/module-shopping-feed/pull/26), and [#27](https://github.com/mage-os/module-shopping-feed/pull/27) with SHO-5. Existing feeds remain delimited unless XML is selected, and the new rules and modifiers are opt-in.

## New capabilities

- **XML output:** Google Shopping, Google Local Inventory, Microsoft, Pinterest, TikTok and Meta have automatic RSS presets with destination namespaces, field aliases, repeated images and nested shipping/tax values. Generic feeds support custom wrappers, item elements, optional columns and CDATA. Select XML explicitly and use an `.xml` filename. OpenAI remains delimited only; Google Promotions retains its separate companion format. See [XML output](../wiki/XML-Output.md).
- **Conditional Value:** Choose fixed text, an attribute, or a percentage adjustment when an All/Any condition group matches, with a separate Otherwise output. For example, mark a product `premium` when its raw price exceeds a threshold. Use it in Columns Map or Replace Empty Values. See [Conditional values](../wiki/Conditional-Values.md).
- **Product Selection:** Include products matching All/Any attribute conditions, including SKU wildcards, image presence, visibility and parent status. Conditions complement existing stock, category and exclusion rules. Parent conditions must match one parent context. See [Product selection](../wiki/Product-Selection.md).
- **Per-column modifiers:** Chain prepend/append, case changes, round/integer/decimal places, date/price formats, Strip tags, Escape HTML and Secure URL on the final mapped value. Drag rows or edit Order with the keyboard. For example, Prepend `Brand: ` followed by Uppercase produces `BRAND: RED SHOE`. Limits run after the chain. See [Columns and directives](../wiki/Columns-and-Directives.md#per-column-modifiers-130).

The parent-inheritance guide now explains the existing four modes, the save-first column selector, and bundle limitations. The dated competitor comparison remains a historical planning document.

## Corrections included

Conditional editors initialize after provider data arrives, preserve literal and structured values, and default new mappings to Static Value. Rule validation covers malformed imports, both output branches, Unicode SKU wildcards and calendar-day comparisons. Preview diagnostics and composite row IDs survive full generation.

XML preserves shipping/image boundaries and multiline wrapper edits. Invalid product text skips the affected row with diagnostics; invalid configuration or file-write failures preserve the prior published file. Optional empty fields are omitted and zero is retained.

Modifiers reject unknown effective column names and unsafe unenclosed entity delimiters, including separators that overlap an entity boundary. Google `promotions_id` and `promotion_id` share one ordered chain; runtime-added variant columns can be targeted. Strip tags preserves text boundaries and removes script/style bodies. Round returns plain decimal text. With XML, modifiers use UTF-8, ignore inactive delimiter settings and retain structured value boundaries.

## Upgrade

Platform and Composer requirements are unchanged. Version 1.3.0 introduces no schema or data patch and does not repurpose Magento's historical `setup_version` as a package version. Composer derives the package version from the release tag.

1. Back up matching application code, database, Composer lock file, feed configuration and accepted output files. Record active schedules and upload destinations.
2. On staging, after the tag is published, update the package:

   ```sh
   composer require 'mage-os/module-shopping-feed:^1.3.0' --no-update
   composer update mage-os/module-shopping-feed --with-dependencies
   bin/magento setup:upgrade
   bin/magento cache:clean
   ```

3. Follow the store's normal DI compilation and static-content deployment process. Compare complete files for each feed/store view before enabling new rules or formats.
4. Test new features on copies of feeds with schedules and uploads disabled. Save/reopen, preview representative products, generate the complete file, and compare row counts, identifiers, prices, inherited values and escaped text.
5. When selecting XML, change the filename and update the recipient's format/URL only after validating the sample. Confirm the destination accepts it before resuming delivery.

Upgrades from before 1.2.5 must also create the Skip from Being Submitted attribute through `setup:upgrade`. Upgrades from 1.2.3 or earlier require trusted SHA256 fingerprints for SFTP destinations. See the [cumulative upgrade guide](../wiki/Installation-and-Upgrade.md).

## Rollback and limits

Do not downgrade a feed configured with Conditional Value, Product Selection, XML or modifiers and assume an older version will honor it. Restore the pre-upgrade configuration/database and matching code/lock file, or remove new directives/rules/modifiers and switch to delimited output with the previous filename before reverting code. Keep schedules and uploads disabled until the restored output is verified.

Price formatting changes representation, not currency. Numeric operations use PHP floating-point arithmetic. Secure URL rewrites the scheme without checking remote HTTPS support. Output limits may truncate HTML entities. Modifiers on structured XML shipping apply to each component; review those values rather than assuming a blanket operation is appropriate.

The preset output-limit key mismatch remains: configure explicit Limit column output rows. OpenAI's Google-compatible preset remains beta with documented contract gaps. TikTok XML field ingestion, other external recipient acceptance, native Nebula rendering and production volume are separate checks. Generated media files remain public; export public catalog data only.
